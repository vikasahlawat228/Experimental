# recaps/

One file per completed session. Created by `daily-learning` at capture.

## Naming

`M<NN>_<slug>.md`. If a module takes multiple sessions, suffix with `_v2`, `_v3` (`M03_request-flow.md`, `M03_request-flow_v2.md`).

## What every recap contains

```markdown
# M<NN> — <Module name> — Session recap

> Date: YYYY-MM-DD · Duration: ~X min · Module: M<NN>

## The one aha
<Single sentence I should walk away believing. This is the success criterion of the session.>

## My verbatim quotes
Captured from the Socratic break and elsewhere. My actual words — not summaries. These are the substrate of future calibration.

- "..."
- "..."

## Engagement signals
<Specific observations from the session — "sharp on data model, hand-wavy on rollout"; "tired at start, sharper after first hook"; "surprised by X." Honest, not punitive.>

## Artifact produced
<Link to or paste of the thing I produced during the Apply move. A diagram, a written critique, a draft, a code sketch.>

## Mastery snapshot (this session)
| Concept | Mastery (1–5) | Notes |
|---|---|---|

## Honest read
- **Strength**: <one specific moment>
- **Gap**: <one specific moment>

## Cliffhanger
<One sentence that creates curiosity for next session.>

## Updates to other files
<What I changed in progress.md, concept-graph.md, learner-profile-overlay.md as a result of this session.>
```

The recap is the most-read file across sessions — it's how the next session calibrates. Make it specific, not generic.
