# modules/

Sequenced learning modules for this topic. One file per module. Generated by `start-learning`; refined by `daily-learning` as understanding shifts.

## Naming

`M<NN>-<slug>.md`. `M01-foundations.md`, `M02-data-model.md`, `M03-request-flow.md`. The two-digit prefix keeps them ordered in the filesystem.

## Anatomy of a module file

```markdown
# M<NN> — <Module name>

> As of YYYY-MM-DD: <one-sentence promise — what I'll be able to do/say after this module>.

## The promise

<One sentence the assistant will use as the "one durable insight" target.>

## Sources to draw on

- `../research-dump/<file>.md` — <why relevant>

## Depends on

- M<NN-1> — <prior module>

## Planned shape

<Optional — what kind of session this wants. New concept? Teardown? Apply-only?>

## What good output looks like

<Filled in over time. The concrete artifact / understanding I'd produce.>

## Recap links

<Auto-filled by daily-learning after each session that touched this module.>
- <none yet>
```

## Modules are living plans

The initial sequence from `start-learning` is a *plan*, not a contract. As sessions reveal what's actually hard or important, daily-learning can reorder, split, or merge modules — but always with my consent. Silent re-planning is forbidden.
